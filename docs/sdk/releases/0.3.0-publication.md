# SDK 0.3.0 publication — 2026-11-03

`@paiflow/sdk@0.3.0` is published. An independent anonymous registry download
matches the approved archive byte for byte, and the installed registry artifact
passes the clean consumer checks below. `beta=0.3.0`; `latest=0.1.0` remains
unchanged. The [preparation record](0.3.0-preparation.md) is historical.

```sh
npm install @paiflow/sdk@0.3.0
```

## Registry verification

- Independently downloaded the exact public tarball and checked SHA-256,
  SHA-512/integrity and every archive file against the approved retained artifact
  before installing or executing it.
- Installed the verified registry bytes in a fresh ESM consumer with lifecycle
  scripts disabled; no source rebuild or local SDK link was substituted.
- All 229 SDK tests passed against the installed artifact.
- ESM imports, public namespace methods and refusal of internal package exports
  passed. Strict NodeNext declarations passed, including decimal-string amounts.
- README onboarding and error examples passed, including strict NodeNext
  declarations with dependency checking enabled. All five standalone examples
  compiled under NodeNext. Payment-server, developer-server and workflow fixture
  checks passed locally; browser and parameterized examples were compile-only.
  Optional Stellar
  example dependency internals used `skipLibCheck=true` for missing upstream
  js-xdr declarations; SDK-only declaration checks used `skipLibCheck=false`.

Checks used Node 22.23.4; repository tooling is pnpm 10.4.1. The SDK's declared engine remains
`>=22.22.2 <23`, ESM and TypeScript declarations, with zero runtime dependencies.

## Acceptance limits

Registry artifact and consumer verification establish package availability and
local consumer compatibility. They do not establish funded execution through the
registry-installed package; that acceptance case remains pending. The earlier
source-packed TESTNET payment is separate evidence and is not relabeled here.

Private-template instance and guarded-configuration clients are packaged, while
their live acceptance remains unfinished. This release does not resolve legacy
public submission findings, qualify arbitrary 40-node topologies, certify mobile
wallets/load/provider-fault behavior, or complete Campaign 2 acceptance. No backend
deployment, contract activation or production/mainnet promotion follows from this
SDK publication.
