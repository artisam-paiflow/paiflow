# D2 — Developer API

> **Statement of Work, Deliverable 2.** Extend the existing developer API to support the
> swapper flow: shared authentication and rate limiting, deployment-scoped API tokens, an
> execute endpoint and an events endpoint, tests, an OpenAPI specification, a Postman
> collection, and documentation with copyable examples. Full wording in the
> [Statement of Work](../../instawards-phase-1-sow.md), section 4.1.

**Target week:** 2 (14–20 September) · **Status:** Not started

## What a user can do when this is done

A partner's backend holds a token scoped to one deployed flow. It sends a single HTTP request
to execute that flow, and polls a second endpoint to watch the resulting on-chain events. No
Soroban knowledge, no wallet integration, and no access to anything beyond that one flow.

## Evidence required

Section 6.1 of the SOW asks for five things:

- [ ] **Public API URL** — the endpoint reachable and responding
- [ ] **OpenAPI specification or Postman collection** — importable, with a worked example
- [ ] **curl samples** — copyable, with a real request and response
- [ ] **Audit log entry** — showing an API-triggered execution was recorded
- [ ] **Transaction hash** — an on-chain swap triggered through the API

{% hint style="info" %}
The transaction hash here must come from an **API call**, and D1's must come from the **visual
builder**. They prove different paths, so one hash cannot serve both deliverables. Both count
toward the swapper-execution metric.
{% endhint %}

## Carried over from D1

Two things follow the swapper into this week.

- **The binaries are good until roughly 11 March 2027.** The swapper's code entry on testnet,
  and the nineteen others the public app instantiates, were extended on 12 September to ledger
  7742749, so the API-triggered swaps here have no expiry to work around. The factory's contract
  instance, which every deploy invokes and which is one of eight contracts with no `extend_ttl`
  call of their own, was extended out of band on 13 September to ledger 7756749 (#460); it needs
  the same again before then. `pnpm contracts:extend-ttl --network=testnet` reports the current
  figures. What the app does
  when an entry has already archived is its own defect, #459: the deploy simulation still
  succeeds, so the user is asked to sign a transaction that cannot land.
- **Three defects in the trigger path are open.** The 11 September QA pass on paiflow.xyz found
  that a blank Email Notify node makes every save of its flow fail (#450), that a successful
  trigger is reported as a failure when the confirmation poll is aborted (#451), and that a
  successful trigger leaves nothing durable on the page (#452). None blocks D1's evidence, and
  none is in this deliverable's scope, but #451 shares the confirmation poll with the path the
  execute endpoint will exercise.

## Scope note

The SOW's out-of-scope list is explicit that this deliverable extends the API for the swapper
only. Bringing the splitter and streamer onto the same `/api/v1` surface is deliberately left
to a follow-on phase, beyond whatever shared groundwork the swapper endpoints need anyway.
