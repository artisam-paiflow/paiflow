# Validation package

> **Statement of Work, week 4 and "Validation Package".** An end-to-end integration test with an
> external wallet; a 3–5 minute technical demo video; an integration guide with curl examples and
> sample XDR payloads; every on-chain receipt's transaction hash; a final CI and typecheck pass;
> and the evidence handoff for the Ambassador Chapter Lead. Section 6.2 of the
> [Statement of Work](../../instawards-phase-1-sow.md) calls this "Deliverable 4"; section 5.1
> lists its six items under week 4.

**Target week:** 4 (28 September – 4 October) · **Status:** In progress. The video, the guide, the
transaction list and both end-to-end runs are public. The final CI report is added on 3 October,
on the commit the package is handed over at. The week is reported in [week 4](../week-4.md), and
the package is summarised for the Chapter Lead on the [handoff page](../handoff.md).

This deliverable adds no new feature. It proves D1, D2 and D3 together, on the public app, with a
real wallet, and puts the record in one place.

## Scope notes

**1. "External wallet" is proven twice, by a person and by a script.** A script cannot prove that a
real wallet works, and a screen recording leaves no machine-readable record, so both were made.
The recording is one unedited take in which **Freighter** signs the deploy and the trigger. The
scripted run signs with a throwaway key in place of the browser wallet, but the envelopes it signs
are the ones the app hands to a wallet, and it keeps every one in full. Each run uses its own
deployment and runs all three deliverables on it: D1's swap from the builder, D2's API execute,
and, in the recording, D3's inputs being used to build the flow.

**2. The API half of the recorded run uses the Postman collection, not curl.** Both call the same
endpoints, prepare, submit and events. The payloads the guide quotes are the scripted run's own,
and in the recording each envelope is signed locally with the Stellar CLI, as the guide does.

**3. The demo video is produced, not a live screen share.** It is cut from screen captures of the
public app, of stellar.expert and of GitBook, with a voice-over read from the committed script.
Anything not happening live is captioned with when it happened. Its closing segment shows the
evidence index where the narration names the handoff page, which had not been written when the
video was cut.

**4. Code changed in week 4 only where the video or the guide would hit it.** A swap payout to a
recipient without a USDC trustline used to fail as a bare "error #13"; it now names the asset and
the issuer the recipient must trust ([`8f81549`](https://github.com/artisam-paiflow/paiflow/commit/8f815491a078d79647667a14c9d9b98619a42cd2)).
The API classifies a simulation revert by its type rather than by its message text, and
`/api/health` reports the build a tester is running
([`98a31cd`](https://github.com/artisam-paiflow/paiflow/commit/98a31cd1b35166f0a7ca92780cb7ab2adb83b2fa)).
Everything else found during the sprint and not fixed is listed as a
[known limitation](../handoff.md#known-limitations).
