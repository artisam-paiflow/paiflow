# D3 — Shared builder inputs

> **Statement of Work, Deliverable 3.** Create reusable builder input components and adopt
> them in the Swapper configuration panel, with unified validation and error rendering,
> component tests, and an accessibility and mobile pass. Full wording in the
> [Statement of Work](../../instawards-phase-1-sow.md), section 4.1.

**Target week:** 3 (21–27 September) · **Status:** Not started

## What a user can do when this is done

Picking an asset, entering an amount, choosing an address or setting a share works the same
way everywhere it appears in the Swapper panel, with the same validation and the same error
messages. The panel is usable with a keyboard and on a phone.

## What "before and after" means here

The improvement is standardisation, not decoration. Today each node type in the builder
implements its own inputs — there are two different asset selectors in the same file, adjacent
to each other — so validation behaves inconsistently and error messages vary. The after state
is one set of components with one validation path.

A screenshot pair of the same panel will look similar at a glance, so the evidence should also
show the change in the code (duplicated input markup removed, one validation schema replacing
several) and, for contrast, a panel that has _not_ been migrated yet. That contrast is also the
argument for adopting these components across the rest of the builder in a later phase, which
this sprint explicitly does not attempt.
